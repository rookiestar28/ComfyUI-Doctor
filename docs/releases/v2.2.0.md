# ComfyUI-Doctor 2.2.0

Changes since [v2.1.0](https://github.com/rookiestar28/ComfyUI-Doctor/releases/tag/v2.1.0).

This release makes the way Doctor displays model replies and stored values safer, adds an opt-in
way to send the workflow with chat questions, keeps workflow diagnostics working when a workflow
contains malformed data, and refreshes the host compatibility contracts.

## Safer display of replies and stored values

- Chat replies are rebuilt in an inert parsed document from an element and attribute allowlist.
  Every link address is judged by its parsed scheme and only the canonical form is written back,
  so entity-encoded or whitespace-split `javascript:` addresses that the previous denylist could
  miss no longer run. Unknown elements are unwrapped, scripts, forms, frames, styles, `svg` and
  `math` are removed, and any failure falls back to escaped text.
- Images in model replies are never displayed. A reply could use an image address to send text out
  in its query string the moment it is shown, without any click. An image now becomes a plain link
  whose text is its alt text (or its address).
- The statistics, settings and chat panels keep response and stored values inert: counts are
  coerced to whole numbers, status and error text is written as text, stored base URL, model and
  key values are assigned as input values, and the pull-request address after a feedback submit is
  linked only when it is an `http` or `https` address.
- Preact is loaded only from Doctor's own `web/lib/` folder. When a bundled copy cannot be loaded,
  Doctor shows the plain chat and statistics panels instead of fetching code from a remote host.

## Chat workflow context

- New setting **Send the workflow with chat questions**, off by default. When it is on, both chat
  senders add the serialized workflow to the request, after the privacy mode has been applied. A
  workflow larger than 256,000 characters is left out whole instead of cut, and a workflow that
  cannot be serialized never blocks the chat. With the setting off, requests are unchanged.
- Chat works with every workflow shape the host serializes. A workflow in the host's serialized
  graph shape previously failed with HTTP 500, and a chat without a located failed node silently
  fell back to the older prompt.
- Workflow truncation is measured on the serialized text of every accepted shape, honors the
  documented hop count (it previously expanded only one hop), prunes named widget values as well as
  positional ones, follows link rows in host-serialized workflows, and ignores an error node that is
  not in the workflow instead of cutting the graph to nothing.
- A saved workflow with large non-node members (subgraph definitions, extras or groups) no longer
  loses every node when it is cut to the token budget. The nodes and their links are kept first,
  followed by the members that still fit, and the members that were left out are named in the
  output.
- The list of missing required inputs for the failed node is now read from the host's node registry.
  It was previously empty for every workflow.

## More accurate diagnostics

- Typed optional inputs that the host frontend marks as optional are no longer reported as
  disconnected required inputs and no longer lower the health score. Broken links and genuinely
  required inputs are still reported.
- A node whose ID is malformed or shared with another node keeps its findings. They carry no
  Locate or fix target, so they can never reach another node. Each group of nodes that share an ID
  is reported once as a bounded `Duplicate Node ID` warning, and subgraph children with repeated IDs
  no longer overwrite each other.
- Node types registered by the running host are treated as known. Common first-party types such as
  `UNETLoader` and `DualCLIPLoader` were previously reported as unknown. Instances of a subgraph
  defined in the same workflow and legacy `workflow>` group nodes are no longer reported as unknown
  either; unregistered types are reported exactly as before.
- One node with an odd field type (a null or list `properties`, a non-finite latent size, or a list
  or dict as a link ID or input type) no longer makes the whole workflow lint fail and drop every
  finding of that check.
- Intent signals keep node IDs exactly as the workflow spells them (`09` is no longer read as `9`),
  a malformed ID or node type skips only that node, and the backend and the sidebar now share one
  list of surrounding-whitespace characters and one set of test vectors for ID validation.

## Settings

- Settings now explains a locked or rebuilt server key store with one fixed, localized notice in
  all nine languages. It says what happened, what to do, and that nothing was changed or sent. It
  shows only that text (never a path, key or server message), clears when the store is healthy
  again, and has no reset action.

## Host compatibility

- Source contract checks cover Desktop frontend `1.43.18`, ComfyUI-pinned frontend `1.59.11` and
  standalone frontend `1.61.8`, including the frontend's extracted packages, the partner-node gate
  path, current asset-enrichment and telemetry helpers, deferred extension setting callbacks, and
  the standalone frontend's new default for named widget restoration.

## Development and validation

- The full-gate scripts install frontend dependencies with `npm ci`, so an acceptance run no longer
  rewrites `package-lock.json`.
- The static outbound-safety check finds HTTP client calls by where the client comes from (the
  policy session factory, an `aiohttp` client session or a raw client constructor, including
  aliased and `with ... as` bindings) and no longer depends on the variable name alone.
- Added tests for group-node navigation inside a real subgraph, for the process-global logger state
  after a route-harness run, and for the opt-in workflow context; removed fourteen unused frontend
  exports behind a guard test; documented the extra `fix_suggestion` event that follows `done` in a
  streamed chat reply.
- Refreshed the secret-scan baseline and marked synthetic test fixtures for the scanner.

## Upgrade notes

- Restart ComfyUI after updating. Python 3.10+ remains supported.
- Chat questions do not include the workflow unless **Send the workflow with chat questions** is
  turned on in Settings. When it is on, node types, connections and widget values such as prompts and
  file names are sent to the selected provider after the privacy mode has been applied.
- Replies no longer show remote images; an image appears as a link with its alt text.
- A workflow with malformed or duplicate node IDs can now show findings on those nodes (without a
  Locate or fix target) and one `Duplicate Node ID` warning per group of nodes sharing an ID.
- For local development, install frontend dependencies with `npm ci` rather than `npm install`.
- Source compatibility checks and mocked UI tests do not establish live-host certification or
  guarantee support for every custom node and malformed workflow.
